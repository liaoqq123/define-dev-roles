# 制作常见问题

按当前现象选用相关条目。表中的负责人是统筹分派修复的对象。独立测试把接收确认、缺陷、阻塞与验收结果写给统筹，开发完成工作后直接向指定测试提测。问题、修复和复测在 Obsidian 关联同一任务。

| 常见现象 | 优先核对 | 归属与验收证据 |
| --- | --- | --- |
| 需求口径变动或批量产物不一致 | 确认适用范围、样式基准、输入规格与实际显示条件，列出样例和完整清单。 | 统筹确认范围与验收，制作方按已定基准复核。同尺寸对照检查一致性，记录抽查范围、已交付项和未覆盖项。 |
| 同一处被多个对话修改，或交接长期无人接收 | 查看原任务的负责人、当前改动和接收记录。区分记录已写入和对话已确认。 | 统筹指定唯一编辑负责人。保留各方未交付改动，在原任务补齐接收或阻塞记录，沿用已有对话。 |
| 文件已交付，实际运行仍取旧版、占位或回退 | 沿正式入口追到实际读取的版本、清单、路径、格式或裁区。核对导入结果和依赖。 | 规格或源文件问题交制作方。导入、映射和回退问题交开发。测试从正式入口分别验证正常加载和缺项回退。 |
| 界面标记与运行环境不一致，或启动到意外入口 | 分别核对配置声明、实际运行程序、启动命令和主入口。比较复现环境与验收环境。 | 开发定位配置和运行差异。提测记录附实际版本、入口和可复现命令。 |
| 单个操作正常，连续操作、关闭或转场时状态错误 | 用真实输入重放问题顺序，检查可见层、输入拦截、焦点、事件完成点和退出时机。 | 开发负责行为和事件顺序，UI 视觉负责样式或版式。测试覆盖结束、取消、重复操作和恢复后的状态，保留原有输入路径的回归。 |
| 信息错位、难读，或显示值与实际结果不符 | 在正常界面及适用窗口尺寸检查对齐、对比和遮挡。追踪数值来源和内部字段的显示入口。 | UI 视觉定义布局和可读性，开发负责绑定和真实数据。测试比较实际画面、结算值及不同窗口下的显示。 |
| 小修调试打开无关窗口或跑完整套件 | 先确认是在启动产品、跑专项测试，还是跑整包验收。选择直接覆盖问题的用例。 | 开发维护验证入口。日常专项能无窗口时用无窗口，画面核验显式选择。专项结果单独保存，完整验收报告对应完整用例。 |
| 日志出现通过，但实际漏测、超时或结果已过期 | 同时检查退出状态、错误输出、用例是否执行完和验证期间输入是否变化。把技术通过和使用体验验收分别记录。 | 开发保证失败传到主测试入口。测试对照待测版本独立复核，并写清通过项、失败项和未覆盖范围。需要时关联可比画面或版本快照。 |
| 工具调用失败或依赖暂缺 | 区分输入缺失、环境不匹配、权限限制和暂时故障。只在有依据时做有限重试，记录恢复条件。 | 当前负责人在 Obsidian 写明错误、已检查项、缺少条件和可继续部分。统筹协调依赖或决定改派。 |

## 最小问题记录

- 关联任务、待测版本和实际入口，附设备或运行条件中与现象有关的部分。
- 写明复现步骤、预期、实际、是否稳定出现和证据位置。
- 标出已定位的边界、拟分派负责人及修复后的可验证结果。
- 分别记录制作自查、开发接入与自测、独立验收。用户明确授权发布的批次再进入发布流程。
